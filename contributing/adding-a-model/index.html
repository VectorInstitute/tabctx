    Add a model¶

    tabctx serves any tabular model that can split its work into encode a training table and predict against the encoding. A model is one class, a backend, plus a few lines of wiring. The cache, admission control, placement, tenancy and HTTP API come with it: none of them import a model, they only use this interface.

    backends/tabdpt.py is a recent, compact example. Open requests for new models: Mitra (#102).

    The interface¶

    class TabularICLBackend(Protocol):
    """A tabular in-context-learning model, wrapped for tabctx.

    Implementations MUST construct a fresh underlying estimator/model
    instance inside every fit() call. fit() mutates instance state (that's
    the whole point -- it's where the training context gets encoded), so
    reusing one shared instance across dataset_ids would silently corrupt
    every cached context that isn't the most recent one.
    """

    name: str

    def fit(self, X: ArrayLike, y: ArrayLike, task: Task) -> Any:
        """Encode the training context. Returns an opaque, backend-owned
        payload that the cache manager retains standalone (the engine never
        inspects it) and later passes back into predict()."""
        ...

    def predict(
        self,
        payload: Any,
        X_test: ArrayLike,
        return_proba: bool = False,
        quantiles: tuple[float, ...] | None = None,
    ) -> PredictOutcome:
        """Run inference against a cached context. Must be a SINGLE
        inference pass regardless of return_proba -- derive predictions from
        probabilities (e.g. argmax) rather than calling predict() and
        predict_proba() separately, since each call is a full forward pass
        over the cached context. A classification's labels are strings,
        whatever return_proba is (backends._outcome).

        quantiles, and any other output in tabctx.outputs (times,
        rmst_horizon, potential_outcomes): a backend gives each output it
        can by taking a keyword argument of that name and filling the
        matching PredictOutcome field, from the same pass as the
        predictions. It is passed only the outputs asked for, and only for
        tasks they are for (the engine checks, and refuses an output whose
        argument its predict doesn't take)."""
        ...

    def context_bytes_hint(self, n_train: int, n_features: int) -> int | None:
        """RESIDENT cost of the context most recently returned by fit(),
        for cache capacity/eviction accounting -- called by the engine
        AFTER fit(), not before, so an implementation can report a real
        measurement (e.g. actual device memory delta) instead of a guess.
        Return None if the backend has no opinion; the engine falls back
        to its own (much more conservative, pre-fit-only) MemoryEstimator.

        Implementations MAY also expose ``fit_peak_bytes_hint() -> int |
        None`` (optional; the engine probes with getattr): the TRANSIENT
        high-water memory of the most recent fit(). That is the
        admission-relevant quantity -- peak is what actually OOMs, and it
        can exceed the resident context by orders of magnitude -- and the
        engine feeds it (not the resident size) back into the estimator's
        admission learning."""
        ...

    What fit and predict receive¶

    • X: a 2-D float32 numpy array. Missing values are NaN. Text columns arrive already encoded as category codes (0, 1, 2, ... in sorted order); a category the training table never had becomes NaN at predict. The model can treat every column as numeric.
    • y: the labels. For classification, any values (tabctx returns them as strings); for regression, numbers.
    • task: "classification" or "regression", or "survival" or "causal" for a model that serves those (below).

    Which tasks¶

    A backend serves classification and regression unless it says otherwise in a tasks attribute (e.g. tasks = frozenset({"survival"})); the engine sends it only those fits, and a fit that names no model goes to the first one that serves its task. A survival or causal fit's y has two columns (tabctx.tasks.split_targets): time and event flag, or outcome and treatment flag.

    Outputs beyond the predictions¶

    tabctx/outputs.py lists what a predict can ask for besides its predictions (quantiles, times, rmst_horizon, potential_outcomes) and which tasks each is for. A backend gives an output by taking a keyword argument of that name in predict and filling the matching PredictOutcome field; it is passed only the outputs asked for, and a request for one its predict doesn't take is a 422 before any work. backends/survivalpfn.py and backends/causalpfn.py are the examples.

    The rules that matter¶

    • A fresh model per fit. fit() must build a new underlying estimator every call; the payload it returns is cached and must not be shared with any other context.
    • One pass per predict. Derive labels from probabilities rather than running the model twice for return_proba=True (tabctx.backends._outcome.classification_outcome does it, and returns labels as strings).
    • Report the context's size. context_bytes_hint() returns the bytes the fitted context occupies, measured after the fit (on a GPU, the allocator's growth), or None to let the engine estimate it.
    • Raise tabctx's errors. Bad input raises InvalidInputError (HTTP 422); a device failure or out-of-memory raises BackendComputeError (507). Anything else reaches the caller as a
    • backends/tabpfn.py shows both.
    • name is the model id clients send as model and see in GET /v1/models, e.g. tabicl-v2.

    Optional hooks¶

    The engine and the server probe for these with getattr, so a first version needs none of them:

    Hook What it buys
    warmup() Load weights at server start, not inside the first tenant's fit.
    fit_peak_bytes_hint() The fit's real peak memory, which the admission estimator learns from.
    dumps_payload() / loads_payload() Compact spill files, e.g. leaving shared weights out. Default: pickle.
    prepare_fit() / fit_prepared() Run CPU preprocessing while another fit holds the GPU.
    may_offload() / host_bytes_estimate() Host-memory admission for fits that stage data in RAM.

    Wire it in¶

    1. The backend, in src/tabctx/backends/<model>.py. Import the model's package inside the module (not in tabctx/__init__.py), so tabctx installs without it.
    2. The server: in src/tabctx/serve/factory.py, add its kind to BackendKind and BACKEND_KINDS, and a branch for it in _build_real_backend.
    3. The client: add its id and tasks to KNOWN_MODELS in src/tabctx/client.py, so the client finds it among a gateway's models (a gateway's listing has no tasks).
    4. Packaging: an extra in pyproject.toml (tabctx[<model>]), added to the Dockerfile's export and to the image check in .github/workflows/docker_image.yml, and a row in the README's models table with the weights license.

    Memory calibration¶

    Admission refuses a fit before it runs out of memory, using an estimate of the fit's peak memory by table shape. A new model starts with the fallback estimate (TabICL's, calibrated on an A100), which is conservative, and then learns from every fit's measured peak.

    A calibrated model gets its own grid of measured peaks: benchmarks/calibrate_memory.py shows how they are measured (it drives TabICL today; point it at your backend), the grids live in src/tabctx/memory/, and factory.py maps each model to them (_REQUIREMENT_CALIBRATIONS, _PREDICT_CALIBRATIONS, _preloaded_observations). This can come in a later pull request.

    Tests¶

    • Unit tests need no model weights: test your backend's own logic with small fakes, and use tabctx.backends.fake.FakeBackend for anything engine-side.
    • An integration test that skips without the package (pytest.importorskip) and checks that predictions through the backend match the model's own package on a small table (tests/integration/test_tabicl_kv_real.py is an example).
    • Accuracy: run benchmarks/eval_real_datasets.py against the model's own package and include the numbers in the pull request.
